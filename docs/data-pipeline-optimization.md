# 数据拉取、缓存与读取优化报告

日期：2026-10-29

数据快照：本机 `.cache/akshare/`（682 只股票收盘价、101 只 OHLC，共 8.86 MB）

复现脚本：`python3 scripts/benchmark_data_pipeline.py --output /tmp/result.json`

## 结论

本轮把“已经缓存过”的最常见路径作为重点：读取时不再重复清洗整表、多个缺口只落盘一次、
能用 OHLC 缓存就不再请求收盘价、损坏缓存不再被元数据永久掩盖。同时用 zstd 降低新写入的占用，
并把远程并发改为进程级上限。

最终，在本机同一份缓存快照上：

| 指标 | 优化前 | 优化后 | 变化 |
|---|---:|---:|---:|
| 682 份收盘价缓存冷读 | 442.7 ms | 318.3 ms | **−28.1%** |
| 682 份收盘价缓存热读（LRU） | 75.8 ms | 60.1 ms | **−20.7%** |
| 101 份 OHLC 缓存冷读 | 543.9 ms | 130.5 ms | **−76.0%（约 4.2×）** |
| 101 份 OHLC 缓存热读 | 249.1 ms | 45.5 ms | **−81.7%（约 5.5×）** |
| 同样数据重写后的 Feather 体积 | 8,693,358 B | 7,268,550 B | **−16.4%** |
| 三个缺口回填时 Feather 写入次数 | 4 | 2 | **−50%** |
| 三个缺口回填耗时（固定响应） | 35.6 ms | 11.9 ms | **−66.7%** |
| 先取 OHLC 再取收盘价的远程请求数 | 2 | 1 | **−50%** |

OHLC 校验摘要前后一致（`3295deb7…0154ba`），说明快路径没有改变价格数据。

## 改了什么

### 1. 读取：只校验，不再全量重洗

`normalize_ohlc_frame` 原来每次命中缓存都会重新 `copy → 转日期 → 数值化 → 四列重建 →
逐行 max/min 修括号 → 去重 → 排序`。缓存文件本身由 `save_cached_ohlc_frame` 写入，
已经满足这些不变量。

现在读取后先用 `_is_normalized_ohlc` 做 O(n) 校验（列、datetime 索引、单调、去重、
float64、无 NaN、high/low 包住 open/close），通过就直接返回；任何一项不满足才走完整修复。
`slice_ohlc_frame` 和 `slice_price_series` 对单调索引改用 `searchsorted` 切片。

收益集中在 OHLC：冷读 544 → 131 ms，热读 249 → 45 ms。对损坏/手工修改的文件仍保留原修复语义。

### 2. 拉取：OHLC 与收盘价互相复用

- 收盘价路径在请求缺口前先看 OHLC 元数据是否已覆盖该区间；覆盖则直接取 `close` 列，
  不再发第二次 AKShare 请求。此前只有“收盘价顺带写 OHLC”的单向复用。
- 同一次收盘价补数中的多个缺口，OHLC 切片先收集，最后合并写一次；原来每个缺口都
  “读整份 OHLC → 合并 → fsync 写回”，缺口越多越慢，且中途失败会丢已成功部分。
- 收盘价和基准的损坏恢复与 OHLC 对齐：元数据声称已缓存、但 Feather 为空/损坏时清空
  区间并重拉，不再静默返回空数据。

### 3. 存储：zstd + 一次落盘

Feather 写入改为 `zstd level 1`。对 783 份真实缓存重写测试：

- 体积 8.69 MB → 7.27 MB（−16.4%）
- 纯序列化写入 204 → 255 ms；叠加真实 `fsync + os.replace` 后为 413 → 397 ms
  （落盘测试中反而略快，说明收益主要来自更少的字节写入）
- 旧 LZ4 Feather 仍可直接读取，无需迁移；文件会在下次更新时自然转为 zstd。

### 4. 正确性顺带修复

- **当日行情污染**：数据源在收盘后仍可能只返回上一交易日。现在只有响应真的包含当天，
  才把 `today` 写入长期区间；否则保留历史并重试，避免“今天永远不再刷新”。
- **LRU 可变对象外泄**：`load_cached_series` 返回独立副本，调用方原地修改不会污染后续命中。
- **全局并发上限**：`BACKTEST_FETCH_WORKERS` 从“每个任务各自 N 线程”改为进程级信号量。
  实测 30 个并发调用峰值为 12，而不是随任务数放大到 36。
- 回退标记元数据增加签名 LRU，避免每个股票重复读 JSON。

## 测试

新增 `tests/test_data_pipeline.py` 16 个回归用例，覆盖：收盘价/基准损坏重拉、OHLC→收盘价复用、
三缺口只写一次、序列副本隔离、zstd 无损读回、OHLC 快路径与修复语义、当日旧响应防护、
同股票并发合并请求。

全量结果：`100 passed, 1 skipped`。跳过项是原有的前端 node 用例（本机未装 node）。

## 边界与后续

- 基准是**离线、OS 页缓存已热**的条件，反映解析/清洗/落盘开销，不包含网络 RTT；
  远程请求收益用固定响应计数衡量，未联网压测。
- `zstd` 需要 pyarrow 支持；项目要求 `pyarrow>=14`，满足。
- **已知限制（未在本轮修复）**：AKShare 前复权价格会随除权除息重算。缓存建立后若发生
  复权基准变化，增量拼接新旧区间可能出现一次性假收益。需要严格口径时，删除对应
  `stock_close*` / `stock_ohlc*` 缓存后全量重拉。要根治需记录复权版本或用重叠交易日
  校验并统一缩放旧历史，建议作为独立改动评估。
